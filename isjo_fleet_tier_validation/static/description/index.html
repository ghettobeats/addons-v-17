📋 Descripción del Módulo

Fleet Tier Validation extiende el módulo nativo de flota (fleet.vehicle) integrando el framework base_tier_validation de OCA para controlar los movimientos de asignación y descarga de vehículos institucionales mediante un flujo de aprobación por niveles configurable, con registro de historial y wizard de comentario obligatorio en cada decisión.

🎯 Beneficios clave:

  • ✅ Flujo de estados: Borrador → Asignado → Descargado / Cancelado
  • ✅ Aprobación multinivel con base_tier_validation
  • ✅ Wizard de comentario obligatorio para aprobar o rechazar
  • ✅ Solicitante + Responsable Institucional como campos separados
  • ✅ Historial completo de cada movimiento (solicitud, aprobación, rechazo)
  • ✅ Transición automática de estado al completarse todas las revisiones
  • ✅ Campos siempre editables durante la validación (estado, conductor, asignado)
  • ✅ Integrado con mitur_fleet_extension y hr.employee

🔄 Flujo de Estados del Movimiento

El campo movement_state controla el ciclo de vida completo de cada movimiento vehicular. Cada transición requiere aprobación de los niveles configurados antes de hacerse efectiva.

📤 Solicitar Asignación

Requiere indicar al menos un Responsable Institucional o un Conductor. Envía el vehículo al flujo de revisión por niveles.

🔁 Solicitar Reasignación

Inicia una nueva aprobación sin cancelar la asignación actual. Limpia las revisiones anteriores y reinicia el flujo.

📥 Solicitar Descarga

Solicita la salida del vehículo de su asignación actual. Al aprobarse, el estado pasa a Descargado.

✖️ Cancelar / Reiniciar

Cancela el movimiento en curso limpiando el asignado pendiente, o reinicia a Borrador para una nueva solicitud desde cero.

🧙 Wizard de Aprobación / Rechazo

Los botones nativos Validar Nivel y Rechazar del framework base_tier_validation están sobreescritos para abrir siempre el wizard fleet.approval.wizard, que obliga a escribir un comentario antes de confirmar la decisión.

✅ Aprobar Movimiento
  • Comentario obligatorio
  • Valida el nivel del aprobador actual
  • Si todas las revisiones están aprobadas, ejecuta _fleet_apply_approved_state()
  • Registra la acción en el historial de movimientos
❌ Rechazar Movimiento
  • Comentario obligatorio
  • Llama a _rejected_tier() del framework
  • Registra el rechazo con el comentario en el historial
  • El vehículo permanece en su estado anterior

👤 Campos de Asignación y Responsabilidad

🕐 Asignar A (Pendiente)
pending_assignee_id
  • Responsable institucional propuesto para la asignación
  • Se muestra su cargo automáticamente (relacionado)
  • Al aprobarse, se convierte en Responsable Institucional
  • Se limpia automáticamente tras la transición de estado
✅ Responsable Institucional
fleet_responsible_id
  • Asignado confirmado tras la aprobación del flujo
  • Campo de solo lectura — lo actualiza el sistema
  • Su cargo también se muestra automáticamente
  • Permanece al solicitar una reasignación de conductor
🚗 Conductor Asignado
assigned_person_id
  • Definido en mitur_fleet_extension
  • Editable incluso durante el proceso de validación
  • Referenciado en el historial de movimientos
  • Filtra solo empleados con is_mitur_driver = True
⚡ Campos Siempre Editables
ALWAYS_EDITABLE
  • state_id — Estado nativo del vehículo
  • mitur_status — Estatus MITUR
  • pending_assignee_id — Asignado pendiente
  • assigned_person_id — Conductor

📜 Historial de Movimientos

Cada acción sobre el flujo queda registrada automáticamente en fleet.movement.history, incluyendo el usuario que la ejecutó, el estado del vehículo en ese momento y el comentario ingresado.

📌 Datos registrados por acción
  • Vehículo relacionado
  • Estado del movimiento al momento del evento
  • Tipo de acción (solicitud, aprobación, rechazo, cancelación, reinicio)
  • Usuario que realizó la acción
  • Asignado institucional y conductor al momento
  • Comentario libre del aprobador/rechazador
  • Fecha y hora exacta del evento
🏷️ Tipos de Acción registrados
📤 Solicitud Enviada ✅ Aprobado ❌ Rechazado ✖️ Cancelado 🔄 Reiniciado

⚙️ Configuración de Niveles (Tier Definitions)

Los niveles de aprobación se configuran desde Configuración → Niveles de Validación (menú del módulo base_tier_validation). El módulo establece los siguientes parámetros fijos en fleet.vehicle:

🔧 Parámetros del modelo
  • _state_field = "movement_state"
  • _state_from = ["draft", "assigned"]
  • _state_to = ["assigned", "discharged"]
  • _cancel_state = "cancelled"
  • _tier_validation_manual_config = False
🎭 Excepciones de validación

Los métodos siguientes se sobreescriben para permitir editar los campos de ALWAYS_EDITABLE en cualquier punto del flujo:

  • _get_under_validation_exceptions()
  • _get_after_validation_exceptions()
  • _get_all_validation_exceptions()
🪝 post_init_hook

Al instalar el módulo se ejecuta un hook que configura automáticamente las Tier Definitions iniciales para el modelo fleet.vehicle, evitando que el administrador deba crearlas manualmente desde cero.

🗄️ Modelos Incluidos

fleet.vehicle

Definiciones de niveles creadas por el post_init_hook al instalar; administradas desde la UI de base_tier_validation
